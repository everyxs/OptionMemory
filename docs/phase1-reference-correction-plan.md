# Phase 1 参考值修正方案（草案）

- 日期：2026-10-31
- 状态：**R3 已于 2026-10-31 批准并执行；R4 暂缓**。原始参考值均未修改
- 适用范围：HEA-Lens-1540 中 701 组合金成分及其 `Smix_ideal`、`lattice_distortion_parameter_delta` 参考值
- 关联证据：`docs/phase1-rules-spec.md`、`scripts/calibrate_delta.ts`

## 1. 先说结论

目前最需要修正的不是“记忆架构”，而是参考值的**计算口径、版本和可追溯性**。

现有证据不能证明原始参考值一定错误。更准确的判断是：

1. 公开 CSV 给出了合金成分和两个描述符参考值，却没有同时给出完整的生成代码、原子半径表和成分精度信息。
2. R3 的大部分参考值能由公开成分复算，但 97 行不能，说明至少存在部分口径或版本不一致。
3. R4 的参考值无法由已测试的常见半径表和 δ 公式复现，因此目前不能判断应修改原值，还是应修改我们对公式的理解。
4. 修正时必须保留原值，不能把“让计算结果接近参考值”当作选择公式的依据，也不能凭经验挑一张看起来合理的半径表。

推荐方案是：

- **R3**：可以制作一个有明确公式和成分来源的 v2 修正版，同时保留原始值用于交叉检查。
- **R4**：先追溯原始生成口径；在口径查明前不宣布“修正完成”。如果最终无法追溯，只能另行制作“标准化替代值”，不能冒充对原始参考值的修复。

## 2. 非专业读者需要的背景知识

### 2.1 合金成分是什么

合金可以简单理解为多种元素按比例混合形成的金属材料。本数据集使用 **at.%（原子百分比）** 表示成分。

例如，某合金含有：

- Fe 50 at.%
- Cr 30 at.%
- Ni 20 at.%

可以理解为：每 100 个原子中，平均约有 50 个铁原子、30 个铬原子和 20 个镍原子。

本数据集中，每条可导入记录包含 36 个元素列；未使用的元素含量为 0。701 条有效成分记录的成分合计均为 100 at.%。

### 2.2 什么是“描述符”

描述符是把一组成分压缩成一个数值，帮助研究者比较不同合金。这里涉及两个描述符：

- `Smix_ideal`：理想混合熵，可通俗理解为**元素混合程度的一个量化指标**。
- `lattice_distortion_parameter_delta`：原子尺寸差异参数，可通俗理解为**不同元素的原子大小有多不一致**。

可以把它想象成把不同大小的球放进同一套货架：球的大小差别越大，排列时产生的“拥挤和不整齐”通常越明显。δ 就是用原子半径差异近似描述这种尺寸不匹配程度的一个经验指标。

这两个值都是由成分计算出来的**派生参考值**，不是每块合金都经过实验直接测得的物理真值。因此，计算它们时必须同时知道：

- 使用了哪一版成分；
- 使用了什么公式；
- 使用了哪张原子半径表；
- 输入成分保留了多少位小数；
- 输出采用小数还是百分数。

只保存一个数值而不保存这些信息，后续就很难复现。

### 2.3 参考值在项目中起什么作用

项目准备让规则 R3/R4 根据成分自动计算 `smix` 和 `delta`，再与数据集自带的 `ref_smix`、`ref_delta` 对拍。

这里的参考值类似“答案卡”：如果公式和输入都正确，计算结果应当接近答案卡。

但如果答案卡本身来自另一版成分、另一张半径表或另一种公式，那么对不上并不自动说明我们的计算错误。反过来，如果我们自己按某公式生成参考答案，再用同一公式与它对拍，就只能证明程序内部一致，不能证明公式选对了。

## 3. 现有数据情况

### 3.1 数据规模与完整性

当前 mnestic 中有 701 组完整的：

- `composition(HEAL####, 成分)`；
- `ref_smix(HEAL####, 参考混合熵)`；
- `ref_delta(HEAL####, 参考原子尺寸差异)`。

公开数据集背景、字段和导入过程见 `docs/hea-lens-survey.md`。原始参考值均保持不变。

### 3.2 R3 的实际情况

R3 使用常见理想混合熵公式：

```text
smix = -8.314 × Σ xi × ln(xi)
```

其中 `xi` 是元素的原子分数，即 at.% 除以 100。

全量 701 行复算结果：

| 项目 | 结果 |
|---|---:|
| 绝对误差 ≤0.001 | 604 行 |
| 绝对误差 >0.001 | 97 行 |
| 通过率 | 86.16% |
| 手册验收目标 | ≥99% |
| 最大绝对误差 | 1.426142879 |

HEAL0001 的例子：

```text
公开成分复算值：12.319371486
原参考值：      12.319697252
绝对误差：      0.000325766
```

这一行可以认为非常吻合。但另一些行差异很大，例如：

| alloy_id | 公开成分复算值 | 原参考值 | 绝对误差 |
|---|---:|---:|---:|
| HEAL0444 | 9.083603018 | 7.657460139 | 1.426142879 |
| HEAL0438 | 9.308069146 | 8.074479345 | 1.233589801 |
| HEAL0441 | 9.323491779 | 8.184198616 | 1.139293163 |

这说明不能简单地把全部原参考值判为错误，也不能忽略这 97 行。

### 3.3 R4 的实际情况

R4 测试的基准公式是常见的 Takeuchi–Inoue 原子尺寸差异公式：

```text
r̄ = Σ xi × ri
δ = sqrt(Σ xi × (1 - ri/r̄)²)
```

其中 `ri` 是元素原子半径。公式本身不长，但不同资料的原子半径定义和数值可能不同，因此“使用哪张半径表”是计算口径的一部分。

开发手册早已给出警告：HEAL0001 用三组常见半径表得到的 δ 分别约为 0.0342、0.0503、0.0414，而参考值约为 0.019037，**均偏离 2–3 倍；半径表或 δ 定义必须通过对拍确定，禁止凭经验选定**。

本次进一步对 701 行测试了：

- HEA 常用金属半径，包含 Mn=1.270 和 Mn=1.350 两种敏感性配置；
- Slater empirical 半径；
- Clementi calculated 半径；
- covalent single-bond 半径；
- 基准 δ、δ×100、δ/2、δ/√2、RMS 平均半径和未加权平均半径等变体。

共 30 个候选组合，结果仍然全部未达到验收线：

| 指标 | 手册要求 | 当前最好结果 |
|---|---:|---:|
| Pearson 相关系数 | ≥0.99 | 0.731799 |
| 中位相对误差 | ≤5% | 22.96% |

“Pearson 相关系数”可粗略理解为：计算值变大时，参考值是否也按相似规律变大。即使把数值整体除以 2，让部分行的绝对差距缩小，也不会改善这个相关性。因此，整体缩放不能解决根本问题。

## 4. 原参考值究竟有什么问题

目前能确认的是以下三点。

### 4.1 参考值缺少足够的生成血缘

公开数据没有同时提供可复现的：

- 描述符生成代码；
- R4 原子半径表及版本；
- 生成参考值时使用的未舍入成分；
- 特殊行的成分处理规则。

这使参考值无法被完整复现。

### 4.2 至少部分 R3 参考值与公开成分不一致

R3 公式简单、无半径表，604 行又能吻合，说明当前读取和计算链路基本正常。97 行不一致更可能来自：

- 参考值使用了公开 CSV 导出前的更高精度成分；
- 某些来源行使用了不同成分口径；
- 数据集不同版本的成分与描述符被混合；
- 个别参考值需要重新核验。

这些是待验证假设，不能直接当成事实，也不能未经核实就把 97 行称为“错误数据”。

### 4.3 R4 的公式或半径定义尚未确定

R4 的问题比 R3 更严重：不仅是少数行不一致，而是现有候选整体都无法解释参考值。

因此，R4 当前不是“挑一个误差较小的公式然后修数据”的问题，而是**原始答案卡的生成规则尚未查明**的问题。

---

## 5. 修正方案的基本原则

1. **原值只读保留**：不覆盖、不删除原始 `ref_smix` 和 `ref_delta`。
2. **修正与替代分开命名**：能证明原值计算错误的才叫修正；因原口径不可追溯而另选标准生成的值只能叫标准化替代值。
3. **公式不由误差大小单独决定**：不能仅因某候选更接近就选择它，更不能凭经验指定半径表。
4. **禁止循环验证**：自己生成的 v2 不能用来证明同一个公式在外部意义上正确。
5. **所有版本均可追溯**：记录成分、公式、半径表、脚本、参数、时间和差异。
6. **未通过验收就不批量派生**：R4 未解除阻塞前，不把 `delta` 派生事实写入正式闭包。

## 6. R3 修正方案

### 6.1 推荐做法

制作完整的 `ref_smix_v2`，统一使用：

- 当前公开 CSV 的成分；
- `R=8.314 J/(mol·K)`；
- 明确的零含量元素处理规则；
- 固定精度的数值输出。

对全部 701 行统一重算，而不是只修改 97 行。这样可以避免同一版本中混用不同精度或不同计算路径。

同时生成新旧对照表，将记录分为：

| 分类 | 行数 | 处理方式 |
|---|---:|---|
| 原值与复算值在 0.001 内 | 604 | 保留为原始交叉验证样本 |
| 原值与复算值超差 | 97 | 使用 v2 复算值，标记 `corrected_pending_source_review` |

### 6.2 为什么合理

- 公式已明确，且多数原始参考值能够复现。
- 修正版的输入和公式完全公开，可由第三方独立重算。
- 保留 604 个原始吻合行，可检查新计算路径是否引入回归。
- 对 97 行保留审查标记，不会把“当前无法解释”伪装成“已经证明原值错误”。

### 6.3 合理性的边界

`ref_smix_v2` 只能证明“按照当前公开成分和指定公式，应该得到什么值”。它不能证明公开成分本身一定准确，也不能独立证明原参考值没有使用更高精度成分。

因此，后续仍应优先向数据集维护方确认 97 行的原始成分精度和生成历史。

## 7. R4 修正方案

### 7.1 第一阶段：先追溯，不修改

向数据集维护方或原始 Excel 数据链路索取：

1. `lattice_distortion_parameter_delta` 的生成代码或 Excel 公式；
2. 完整原子半径表、单位和文献来源；
3. 生成描述符时的原始成分精度；
4. 是否存在只使用主要元素、忽略微量元素或重新归一化成分的特殊处理；
5. 参考值是小数形式还是百分数形式。

只有能复现原始参考值，才能判断具体哪些值需要修正、哪些只是我们的公式理解不同。

### 7.2 第二阶段：用独立证据确认口径

若取得新的公式或半径表，应同时通过：

- 全部 701 行对拍：Pearson ≥0.99，中位相对误差 ≤5%；
- 文献中已知 δ 的独立合金样例；
- 单位和数量级检查，例如 0.019 与 1.9% 是否只是表示形式不同；
- 对特殊成分和微量元素处理的逐行核验。

满足这些条件后，才能把该口径登记为 R4 的正式计算规则。

### 7.3 第三阶段：只有原口径确实无法追溯时，才提出标准化替代方案

如果最终无法获得原始生成规则，可以由项目负责人和材料领域评审者决定是否建立 `ref_delta_standardized_v1`。

该版本必须：

- 明确写出所选公式及半径表，不再称为“恢复原参考值”；
- 说明选择依据来自公开定义和独立文献样例，而不是因为它与原参考值误差最小；
- 对全部 701 行统一重算，保留原 `ref_delta` 供后续研究；
- 标记为 `standardized_unverified`，直到有独立验证；
- 单独报告分布、异常值和 `delta>0.06` 数量，不与原参考值混算。

**当前数据尚不足以批准这一阶段的具体半径表。** 因此，本草案不建议现在选定任何 R4 半径表。

### 7.4 明确不采用的做法

- 不因为某组半径“常用”就直接选定。
- 不将 δ 统一除以 2 或 3 来迎合参考值。
- 不用 701 行参考值反向拟合 36 个元素半径，再把拟合结果当作物理半径表。
- 不删除或覆盖无法解释的原参考值。
- 不用自行生成的替代值去证明同一公式已经通过外部验证。

这些做法虽然可能让指标暂时好看，却会破坏参考值作为独立答案卡的意义。

## 8. 数据版本与血缘设计

建议并存以下版本：

| 数据 | 含义 | 当前建议 |
|---|---|---|
| `ref_smix` | 原始参考值 | 保留，不修改 |
| `ref_delta` | 原始参考值 | 保留，不修改 |
| `ref_smix_v2` | 公开成分 + 固定 R3 公式的修正版 | 评审后可生成 |
| `ref_delta_v2` | 查明原始口径后的修正版 | 只有追溯成功才生成 |
| `ref_delta_standardized_v1` | 原口径无法追溯时的标准化替代值 | 需另行审批，不在本次自动执行 |

每条新记录应携带：

- 对应 composition fact 的 ID；
- 公式和规则 ID；
- 半径表名称、版本和来源（R4）；
- 重算脚本版本；
- 原始值、修正值和差异；
- 质量状态及是否经过独立验证。

写入仍应通过 `memory_set_batch` 和 ν 门。原始值是否转为 `archived`，留待 Phase 2 修订传播能力就位后另行决定，不做物理删除。

## 9. 验收方式

修正后的验收必须区分两种一致性：

### 内部一致性

证明数据管线按声明口径工作：

- 701 行成分均能解析，合计为 100 at.%；
- 所有结果均为有限数值，单位和精度一致；
- 同一输入和版本重复计算结果完全一致；
- 每条 v2 记录都能追溯到成分、公式和脚本。

### 外部一致性

证明声明口径有独立依据：

- R3 的 604 个原始吻合行继续通过原容差；
- R3 的 97 个修正行保留完整差异清单并等待来源核验；
- R4 使用文献中已知 δ 的独立合金样例验证；
- R4 不能用自己生成的 v2 作为唯一正确性证据。

## 10. 评审决策与执行状态

1. **R3 已批准并执行（2026-10-31）**：生成 701 条 `ref_smix_v2` 和 701 条 `reference_quality`；604 行为 `original_match`，97 行为 `corrected_pending_source_review`。重跑 inserted=0 / skipped=701，原始 `ref_smix` / `ref_delta` 签名未变化。执行脚本：`scripts/repair_ref_smix_v2.ts`。
2. **R4 暂缓**：先向数据集维护方追溯生成代码、半径表和成分精度。
3. 在追溯结果返回前，维持 R4 阻塞，不批量派生 `delta`。
4. 只有原口径无法追溯且确需继续项目时，才另行评审标准化替代方案及其独立验证集。

本方案的核心不是尽快让所有数字“对上”，而是让每个修正后的数字都能回答：**由哪份成分、哪个公式、哪张半径表、哪个版本计算而来，以及我们凭什么相信它。**
