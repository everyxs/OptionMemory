# Bilingual documentation and runtime policy

This repository supports English and Chinese without translating stored user content or rewriting historical evidence.

## Canonical model

- **English is canonical for new development documents, code comments, and runtime messages.**
- Chinese remains available through companion documents and optional runtime localization.
- Existing Chinese documents remain valid historical sources until a reviewed English companion exists.
- No system process automatically translates facts, captured memories, Markdown sources, IDs, acceptance logs, or evidence.
- `gate`, statuses, reason codes, relation names, field names, namespaces, versions, memory URIs, and idempotency keys are language-independent.

## Companion documents

Use a Chinese suffix for the companion of an English canonical document:

```text
README.md
README.zh-CN.md
docs/phase4-acceptance.md
docs/phase4-acceptance.zh-CN.md
```

Each document declares:

```yaml
lang: en | zh-CN
canonical: <path used by new development>
translation_of: <companion path, for translations>
translation_status: reviewed | original-source | draft
source_commit: <source revision>
reviewed_at: <YYYY-MM-DD>
```

Link the companions near the title. Update both versions when behavior, scope, acceptance criteria, or non-goals change. Historical acceptance evidence is not rewritten merely to make languages consistent; add an explanatory follow-up instead.

## Runtime localization

- `OPTIONMEMORY_LOCALE=en` selects English; `zh-CN` selects Simplified Chinese.
- The default preserves each component's previous behavior. Existing English errors remain English by default; existing Chinese R3 findings remain Chinese by default.
- Stable reason codes are machine contracts. Only human-readable messages are localized.
- Parser and recall behavior is versioned independently of host tool counts and package versions.
- Unchanged source text retains its original `content_hash`, document ID, chunk ID, and superseding chain.

## Bilingual extraction and recall

Markdown extraction and R3 claim validation recognize both languages. Recall uses a versioned token estimator and an explicitly scoped bilingual domain-term map. Cross-language recall claims are limited to tested mappings; they are not claims of general multilingual semantic search.
